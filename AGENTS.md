# Портфолио Евгения Горлинского — правила для агентов

Этот файл читают Codex (AGENTS.md) и Claude Code (через CLAUDE.md → `@AGENTS.md`). Правила общие для обоих.

## Что это за проект

Портфолио продуктового дизайнера. Задача сайта (JTBD): **когда рекрутер или дизайн-лид за 2–3 минуты решает, звать ли на интервью, он хочет увидеть, как я думаю и к какому результату пришёл, чтобы не созваниваться вслепую.**

Отсюда приоритеты: мало кейсов, но глубоких; путь «проблема → решение → результат → ограничения»; контакт в один клик; честные цифры с оговорками.

## Стек

- Astro 5 + MDX — страницы и кейсы. Кейс = файл `src/content/cases/<slug>.mdx`.
- React 19 — только интерактивные прототипы и анимированные компоненты (острова `client:visible`).
- Tailwind CSS 4 — токены в `src/styles/global.css` (`@theme`). Никаких hex в компонентах.
- Motion (`motion/react`) — микроанимации. GSAP — только по навыку `portfolio-motion`, если нужен scroll-сторителлинг.
- shadcn CLI + реестры `@magicui`, `@aceternity` в `components.json`; 21st.dev и affectUI — по URL. Подробно — навык `portfolio-components`.
- Деплой: GitHub Pages через `.github/workflows/deploy.yml` на каждый push в `main`.

## Архитектура (не ломать)

- Главная (`/`) — интро, сетка карточек кейсов, «Интерфейс крупно», «Как я работаю», «Мой путь».
- Карточка открывает кейс **в боковой панели поверх главной**, как в Notion. Но у каждого кейса свой URL `/cases/<slug>`: ссылку можно отправить отдельно.
- Технически `/cases/<slug>` рендерит главную + открытую панель (`CasePanel`). Переходы — Astro `ClientRouter`, позиция скролла главной сохраняется.
- Закрытие панели: крестик, Esc, клик по подложке → `/`.

## Команды

```bash
npm install          # ставит зависимости и синхронизирует навыки в .claude/skills
npm run dev          # http://localhost:4321
npm run build        # проверка перед пушем — обязательна
npm run skills:install  # внешние навыки (shadcn, magic-ui, emil, gsap)
npm run skills:sync     # после правок в .agents/skills
```

## Навыки

Источник правды — `.agents/skills/` (Codex читает отсюда). `.claude/skills/` — копия для Claude Code, обновляется `npm run skills:sync`. **Правь только `.agents/skills`.**

| Навык | Когда брать |
|---|---|
| `portfolio-case` | Новый кейс, правка кейса, перенос из Notion |
| `portfolio-components` | Нужен компонент, блок, эффект, прототип |
| `portfolio-motion` | Любая анимация или переход |
| `portfolio-deploy` | Выкатить правки, домен, проверка деплоя |
| внешние: `shadcn`, `magic-ui`, `emil-design-eng`, `gsap-*` | Ставятся `npm run skills:install` |

## Правила работы

1. **JTBD → сценарий → состояния → интерфейс → микротексты.** Не начинай с визуала.
2. **Перед крупными изменениями покажи план** (новая секция, смена архитектуры, новая зависимость).
3. **Уважай дизайн-систему сайта:** токены из `global.css`, компоненты из `src/components`. Новый компонент — только если задачу нельзя решить свойством существующего.
4. **Микротексты — информационный стиль:** конкретно, коротко, без канцелярита. Ошибка = что случилось + что делать.
5. **Состояния обязательны** у интерактива: пусто, загрузка, ошибка, успех, disabled, edge cases.
6. **Доступность:** контраст AA минимум, фокус виден, `prefers-reduced-motion` уважается, у картинок осмысленный `alt`.
7. **Цифры в кейсах — только из исходника** (Notion, отчёты). Не округляй и не усиливай. Оценки помечай как оценки.
8. **Данные в макетах — демонстрационные.** Не публиковать реальные имена клиентов и персональные данные.
9. Перед коммитом: `npm run build` без ошибок. Коммиты — по-русски, коротко: «Кейс ЭПЛ: добавил прототип состояний водителя».
